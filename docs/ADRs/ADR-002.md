# ADR-002: At-Least-Once Execution Semantics

## Status
Accepted

## Context
In distributed computing across network boundaries and worker processes, guaranteeing "exactly-once" execution of external side effects (e.g. sending emails, debiting accounts, triggering third-party webhooks) is mathematically impossible when workers can crash or networks partition after the external effect is initiated but before completion can be acknowledged in the database.

## Decision
QueueForge explicitly provides **at-least-once execution semantics**. 
- Submission deduplication is guaranteed via tenant-scoped idempotency keys.
- Worker task handlers must be designed to be idempotent when side effects cannot be safely repeated.
- Random cryptographic lease tokens fence stale database state updates, but cannot physically undo external side effects already dispatched to third-party endpoints.

## Consequences
- **Positive:** Transparent, honest system contract aligned with distributed systems realities (such as AWS SQS visibility timeouts).
- **Positive:** Prevents silent job loss during crashes, unexpected terminations, or transient network partitions.
- **Negative / Trade-offs:** Handlers performing non-idempotent actions must use external idempotency keys or distributed locking mechanisms at the domain application level.
