# ADR-004: Lease Duration and Recovery Timing

## Status
Accepted

## Context
When a worker crashes, loses power, encounters an unhandled panic, or is partitioned from PostgreSQL, its active jobs become abandoned in `running` status and its tenant concurrency slots remain occupied. A mechanism is required to safely detect abandonment and requeue or dead-letter the job without false positives.

## Decision
- Default job lease duration: 60 seconds (`QF_DEFAULT_LEASE_DURATION`).
- Worker renewal interval: 20 seconds (`QF_LEASE_RENEW_INTERVAL`), enforcing a 1:3 renewal ratio.
- Monotonic in-process timers trigger renewals. PostgreSQL `clock_timestamp()` is authoritative for lease expiry and recovery decisions to avoid clock skew discrepancies across servers.
- A background recovery loop scans for `status = 'running' AND lease_expires_at <= clock_timestamp()` every 5 seconds using `FOR UPDATE SKIP LOCKED`.

## Consequences
- **Positive:** Abandoned jobs are reliably reclaimed within ~65–70 seconds after an ungraceful crash.
- **Positive:** Stale workers attempting to renew or commit results after expiration are fenced out because the conditional update `WHERE lease_token = $token AND lease_expires_at > clock_timestamp()` returns 0 rows.
- **Negative / Trade-offs:** Very short tasks incur minor renewal overhead if they run past 20s. Handlers must respect context cancellation if lease renewal fails.
