# ADR-006: Schedule Misfire Behavior and Occurrence Uniqueness

## Status
Accepted

## Context
Recurring schedules configured with cron expressions can miss their scheduled run times due to scheduler service maintenance, database restarts, or transient network delays. A clear policy is needed to govern what happens when the scheduler resumes.

## Decision
1. **Expressions:** Standard five-field cron format (minute, hour, day-of-month, month, day-of-week) parsed with `robfig/cron/v3` in an explicit IANA timezone. Seconds are rejected.
2. **Grace Window:** Configurable `QF_SCHEDULE_MISFIRE_GRACE` (default 30 seconds). If `now - next_run_at <= grace`, the run is considered normal lag and executed immediately.
3. **Misfire Policies:**
   - `skip`: Do not generate jobs for missed runs. Record `last_skipped_at` and advance `next_run_at` to the next future occurrence.
   - `catch_up_one`: Generate exactly one job for the most recent missed occurrence, then advance `next_run_at` to the next future occurrence.
4. **Occurrence Uniqueness:** The partial unique constraint `CREATE UNIQUE INDEX jobs_schedule_occurrence_uq ON jobs (schedule_id, scheduled_for) WHERE schedule_id IS NOT NULL` enforces that concurrent scheduler replicas never insert duplicate jobs for the same occurrence.

## Consequences
- **Positive:** Prevents dangerous avalanche bursts of queued jobs after prolonged downtime.
- **Positive:** Provides tenants clear control between catching up once vs skipping missed runs.
- **Negative / Trade-offs:** Does not support catching up every individual missed interval, which was explicitly chosen to protect worker pools from oversubscription.
