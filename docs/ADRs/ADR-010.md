# ADR-010: Benchmark Protocol and Honest Reporting

## Status
Accepted

## Context
Engineering portfolio and infrastructure projects frequently quote unsubstantiated, fabricated, or cherry-picked throughput metrics (e.g. "1,000,000 ops/sec" running purely in RAM without fsync or network overhead). 

## Decision
QueueForge mandates an empirical, transparent, and reproducible benchmarking methodology:
1. **Full Environment Transparency:** Every benchmark report must publish exact hardware (CPU, RAM, OS), PostgreSQL version and durability settings, Go version, commit SHA, and connection pool configurations.
2. **Standard Metrics:** Reports must measure and publish p50, p95, p99 latencies, arrival throughput vs completion throughput, error rates, database connection utilization, and slot leak reconciliation counts.
3. **No Fabricated Claims:** Zero-loss or throughput claims must be strictly grounded in automated integration and chaos tests.

## Consequences
- **Positive:** QueueForge maintains technical integrity, credibility, and high portfolio rigor.
- **Positive:** Clear baseline performance profiles allow users to accurately capacity-plan their deployments.
- **Negative / Trade-offs:** Stated numbers (~400 enqueues/sec on single-node Postgres with full durability) are honest rather than marketing exaggerations.
