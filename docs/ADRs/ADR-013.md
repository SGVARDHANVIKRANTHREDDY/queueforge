# ADR-013: Skip Contended Tenants When Claiming Instead of Idling

## Status
Accepted. The *intent* (a contended or saturated tenant must never make a worker idle) is preserved; the retry loop described below was replaced by the set-based slot assignment in [ADR-015](ADR-015.md), where a contended slot simply counts as "not free".

## Context
`ClaimJob` picks the globally best (priority, run_at) job among tenants that have a free execution slot, then locks one of that tenant's slots with `FOR UPDATE SKIP LOCKED`. The eligibility check is a plain `EXISTS` (no lock), so it can pass while another worker is mid-claim on the same slot. The original code then returned "no work", leaving the worker idle until the next poll even though other tenants had runnable jobs.

Reproduced by `TestClaim_DoesNotIdleWhenTopTenantSlotIsContended`.

## Decision
If the slot lock fails, remember that tenant and re-run the candidate query excluding it (up to 8 tenants per call), all inside the same transaction. Priority order is preserved among the tenants that remain.

## Consequences
- A hot tenant can no longer cause head-of-line blocking for other tenants' workers.
- Jobs locked by earlier failed candidates stay locked until the transaction ends (milliseconds); other workers skip them via `SKIP LOCKED`, which is what we want since that tenant has no free slot anyway.
- Bounded work: at most 8 extra round trips in the pathological case.
